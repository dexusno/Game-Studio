# Build system mechanics — expedition proposal

2026-09-13. Systems designer's proposal for the owner's new build-system goal. **No implementation or fun claim.** The existing 0.5 Extraction career and its saves remain separate. Development timeline is not a constraint. This document owns the mechanical rules; the economy designer owns complete offer/purchase sequences and the producer owns the integrated game promise.

## Recommendation and structural change

Make the magnet a configurable salvage machine whose tools alter how the player manipulates a worksite. A run has four linked sites, intervening depots and a final visible machine-core recovery. The objective is to free, secure and return the core; salvage also improves the current rig and earns refining rewards. Choosing an optional hazardous route should expose a worthwhile component or build opportunity, rather than merely increasing a hidden score.

The current structure cannot carry the requested system unchanged:

- Permanently installing every purchased upgrade eventually eliminates build choice. Preserve ownership/discovery, while restricting each expedition's installed equipment.
- An inert tray and unrestricted time make speed, interception and spatial control difficult to justify. Sites need mechanisms, moving material, obstructions and telegraphed machine hazards that respond to the same physical rules as salvage.
- Four smelts make almost every decision about value per load. Replace that active limit with a finite manipulation battery. Keep unrestricted thinking through a real planning pause.
- Multiplying salvage value must not let an early lucky module buy every other module. Refining rewards can pay actual money through bounded, visible milestones; the physical mission remains independently completable.

Keep attraction, momentum, selective disassembly, clear mass, real furnace payout and recognizable scrap. The broader expedition, mechanisms and loadout system are new work. A static shop with thirty entries is not an adequate substitute.

## Run and equipment constraints

**Proposed run:** choose one of four usable starter actives, enter four sites, buy/fix the rig at three depots, complete the final core operation and evacuate. Unlock two further starter families through demonstrated interaction, not mandatory grinding. All six families remain part of the full design even if the first experiment implements fewer.

Equip **two active tools and four passive slots**. A keystone can occupy two passive slots. There is no additional power-budget meter. Fitting is free at depots; two active controls preserve a manageable input vocabulary. Each active exposes its current operation and next cost. Ordinary attraction, release, drop, inspect and bank remain available to every rig.

Blueprint discoveries, collection and run records persist. Installed run modules and run credits are reconstructed for a new expedition. Archive a successful build for inspection and non-progression practice; do not automatically equip the entire permanent collection. This reset structure is a recommendation for a new mode and must be explained plainly before the first departure. Existing career progress is not converted or deleted by this proposal.

Economy handoff: 12 starting run credits; site-clear awards 10/12/14 before the finale; each of those sites has two visible refining milestones paying 2 credits once apiece. Thus 48–60 credits are available before the finale, excluding sale proceeds. A starter is free; ordinary post-site rewards are **priced offers**, with at least two independently useful, affordable module offers, not universal free modules. Each must function with the rig's available capabilities; a hypothetical future purchase does not satisfy that guarantee. Precharge never substitutes for either module offer. Difficult optional salvage may yield a zero-purchase-basis module. Selling returns 50% of actual paid price. A non-stacking 4-credit depot precharge may start the next site at 120 battery instead of 100. Exact output thresholds require generated-site feasibility checks.

## Battery, input and danger clock

These are explicit experimental values, not settled balance:

1. A site begins with **100 battery**. Waiting, inspecting, moving an already secured haul, releasing the field, dropping, and unloading cost no battery. There is no idle recharge. At zero battery the player can still unload secured cargo or evacuate; no paid tool may operate.
2. A baseline attraction activation costs **6**. Before activation, highlight multiple available connected groups in the aimed 110-unit field. Resolve nearest-to-aim then stable ID, retaining whole groups that fit the current hard attachment limit; display selected mass and unsafe-load warning. The preview and commit use the same selection.
3. One LMB press or Space activation commits that snapshot. The magnet physically attracts those objects; steering during the pull remains meaningful. It cannot acquire newly encountered objects by sweeping the whole site while held. **1.2 seconds is a maximum physical pull window, never a mandatory wait after objects settle.** Holding does not automatically buy another activation. Another deliberate activation is needed for further material.
4. Invalid/empty input costs nothing. Energy is committed when the first valid physical operation begins. Cancelling or releasing afterward retains moved objects and spent energy; no refund/recast exploit. Targets that become invalid are not silently replaced. A pending paid action is never replayed merely by resuming input.
5. Dropped material remains recoverable, but reacquiring it requires another real activation. A broad pull of several loose pieces therefore competes favorably with repeatedly collecting single pieces; there is no arbitrary unload tax. Active tools have the flat costs listed below. A secondary operation either reserves its declared extra cost in the preview or has a finite explicitly free allowance. Proposed controls: LMB/Space baseline attraction, Q/F installed actives, E contextual unload/interact, RMB drops the entire haul recoverably. Releasing LMB or switching the field off retains secured cargo. The tutorial must demonstrate field-off, whole-haul drop and E banking through their different visible outcomes.
6. **Unpaused world time** advances machine hazards, projectiles, physical casts and the unsafe-haul fuse. Idle battery is free, but waiting inside a live press lane is dangerous. **Planning/Pause freezes all of these clocks**, including a held hot cell and unfinished service action. Planning allows inspection and ghost previews, not world movement. Resume restores exact elapsed time, paid energy, target identities and pending outcomes. Focus loss does the same.
7. Keep one contextual unsafe-haul fuse rather than another general strain bar. The baseline rig safely carries 24 kg and refuses attachment above 36 kg; more than 24 kg or a held hot component starts a provisional 3-second fuse on the shared world clock. Quench **spills the entire haul recoverably and spends 12 battery once**, clamped at zero. It does not arbitrarily delete the most valuable piece, recharge anything, or charge the same incident again through overlapping fuse/impact callbacks. A real crusher, collision or heat interaction may cause its stated physical damage; show that causal consequence. The unique mission core remains recoverable even after an incident, although its quality and associated reward may decline. Already banked mission rewards and discoveries persist. Zero battery allows moving and dispatching a secured objective, unloading scrap, or selecting evacuation; it never traps the player in an impossible state. Choosing evacuation before the site's physical objective ends the attempt and forfeits the unfinished site's reward and any unbanked cargo left behind. The objective receiver accepts the core; the furnace accepts scrap and cannot accidentally melt the unique mission object. Archived module discoveries remain safe.

**Unresolved feel hypothesis:** a bounded activation may harm the continuous sweep feel. Compare it directly with continuous attraction using equivalent finite energy accounting. The critic rejected per-piece click-and-wait collection; this specification does not adopt that. If people describe the bounded field as repetitive clicking, change the input/energy coupling before expanding content.

## Reusable rule vocabulary

A module definition contains: identity and description; slot/cost; required capabilities and conflicts; trigger; eligibility; target selector; operations; resource cost; risk; limits; feedback; and save version. The catalogue grows through combinations of shared primitives. Do not advertise a new primitive as data-only work.

| Layer | Initial vocabulary |
| --- | --- |
| Events | Manual action committed; grip settled; selected link severed; body impact; source discharged; tether tension reached; field transfer settled; structure released; smelt committed |
| Targets | Explicit aimed object; committed group; hit object; severed neighbors; reachable conductive component; marked endpoint; source/destination field; carried material meeting a filter |
| Operations | Apply impulse; detach links; transfer ownership; join material into a body; launch a body; conduct finite charge; bind a physical tether; alter a support/constraint; place a finite field; apply/consume a status; transform material; settle a refining result |
| Shared tags | Material, conductive, brittle, hot, fragile, intact, anchored, mass, original-source identity, used-as-ammunition, discharged, marked, player-created |
| Costs/risks | Battery, consumed physical material, occupied slot, loss of intact quality, exposed position, warning before hazardous propagation; no invisible generic “balance penalty” |

### Deterministic resolution and finite chains

1. Capture a manual command and unique root-action ID. Select targets and show mass, cost and likely hazard. Validate ownership, battery and mechanism state. Reserve all guaranteed costs; commit once.
2. Apply declared preparation in this order: material/input transformation → targeting/geometry → force/transfer → collisions/state transitions → reactive children → bank settlement. Break ties by equipped slot then stable module ID, never frame rate or unordered container traversal. The player-facing build panel displays this order; it is not a hidden drag-to-program puzzle.
3. A child carries root ID, parent ID, original material IDs and visited targets. Each `(root, module, target, operation)` fires once. A conduction edge visits a target once per discharge; a source can discharge only its remaining finite charge. Generated effects do not impersonate a manual activation.
4. Reactions can trigger other compatible reactions. To stop a loop, block the repeated edge or already-consumed source rather than disabling every secondary interaction. Recatching, dropping or welding material does not mint a new reward identity. Splitting/welding conserves total source mass and value; transformation consumes a source and records the resulting lineage.
5. A module cannot refund energy from energy it just generated. Energy returns require a distinct, depleted world source. Any free recursive effect has a stated finite allowance. Proposed protection ceilings: 8 reaction generations and 64 effect operations per root action; coalesce cosmetic particles separately. If legal advertised builds hit that ceiling, revise execution/caps or card copy before shipping. Never silently truncate normal promised power.
6. Bank money/refining milestones and commit discovery records through one idempotent ledger keyed by site and original source IDs. The entire pending action, reserved cost, source depletion and queue progress survive saves. Pause, cancellation and retry cannot duplicate payout or remove spent costs.

For the original twenty rows, the active itself grants its named capability. Jaw, Crack Follower and Intact Recovery require `Sever`; Fuse, Slug Press, Rebound Plate and Cyclone require `Launch`; Ground Clip and Closed Circuit require `Arc`; Counterweight Hook, Twin Anchor and Walking Gantry require `PhysicalTether`; Flow Splitter requires `FieldTransfer`. **Conductive Tether requires an actual tether creator and an arc capability for powered use.** The two active slots make that an Arc + Winch build, rather than an unexplained free tether in a Rail + Arc build. Functional-assembly and source-loop keystones require their corresponding authored opportunity tags.

**Arc starter contract:** its 8-battery manual pulse creates exactly one internal charge, enough to actuate one chosen ordinary terminal reached by the actual conducting path. Show the selected terminal before committing; one pulse cannot silently actuate every connected terminal. Internal charge dissipates after that operation and is tagged `RigOrigin, NonRechargeable`. It can neither recharge the rig nor be sold, duplicated, cached by dropping a conductor, or converted into an external-source payout. A finite external battery has its own world-source ID and remaining charge, and can power further branches; it is an optional amplification opportunity. Every starter site must have useful ordinary-terminal interactions, such as releasing a salvage catch or parking a moving arm, plus a physical fallback. The Arc starter cannot depend on finding a rare live source before it does anything useful.

More expensive does not mean universally better. Buying a keystone can displace two excellent ordinary supports. Six especially clear rule changes are Slug Press (many pieces become one physical tool), Ratchet Pawl (leave a load supported), Induction Bridge (cross a gap), Escapement Relay (physical event activates the next terminal), Reaction Frame (route an opposite force) and Field Loom (change a projectile's reachable route). Each needs its stated opportunity before it counts as successful variety. Capstone second ranks are deliberately excluded from this increment: a later rank must add a distinct operation and earn its slot/economy complexity; catalogue breadth already provides the present choice.

Two cross-family acceptance chains:

- **Surgery + conduction:** an alloy conductor is trapped in cheap iron and too bulky to place in a narrow terminal gap. Extraction frees it; ordinary placement or a tether completes a circuit from a finite live source to a remote latch. Extraction alone cannot actuate that electrical shortcut; Arc alone has no valid conducting path. A basic service route still completes the mission.
- **Demolition + rigging:** several small iron pieces cannot individually counterbalance a heavy supported assembly. Slug Press joins the same mass into a body accepted by the hook; Anchor Winch then lifts the intact assembly rather than destroying it. Launching that slug would be a different valid choice with a different outcome. Nothing creates bonus mass by repeatedly welding.

**Slug Press input and payment:** the Rail Impeller's visible ammunition preview identifies the selected carried iron pieces. With two or more selected pieces and Slug Press installed, that active button (Q or F, according to its equipped slot) reads **WELD — 4 BATTERY**. One deliberate press confirms preparation, spends 4, and creates the single physical slug; it does not fire. The preview then changes to **LAUNCH — 8 BATTERY** for that selected body. A subsequent deliberate press pays 8 and launches. Selecting an existing single body allows the normal launch action without another weld. Welding does not arm an automatic shot: pressing the other equipped active, Anchor Winch, can use the retained paid slug as a counterweight. RMB always drops the entire haul recoverably, including the welded body; a later reacquisition is another paid operation. Changing aim before committing preparation leaves material and battery unchanged. Save/reload preserves the welded source lineage, spent energy and the next operation; it cannot replay the paid weld or refund its cost. No additional active slot, hidden firing command or free world-changing cancellation is introduced.

An additional sequencing check for the economy's artillery path: **Impact Fuse + Rebound Plate** first resolves the ordinary collision and whether the body survives. Rebound redirects only a surviving body's remaining impulse. Fuse schedules one delayed burst (provisional 0.35 seconds), following the surviving body's position and consuming its remaining ammunition integrity when it bursts. A body destroyed by the initial collision cannot bounce; its burst retains the recorded impact origin. Preview that branch honestly. The delayed burst is a child of the original action, never a fresh manual shot or a second eligible rebound.

## Final core: six routes through a real operation

The core weighs **20 kg**, so every baseline 24 kg rig can carry it when empty. It is initially anchored, not an ordinary extractable pickup. The visible operation has: an accessible preload clamp, a second fitting partly covered by movable ballast, a third within a sweeping-arm window, and a press lane separating the released core from the depot. Show the actual three fittings and connections; do not hide tiny screw hunts.

Universal fallback uses **three different physical conditions**, not three identical service bars. First, pull the preload collar toward its marked relief stop while the core rests in the visible cradle. Second, move the obstructing ballast into its side catch to uncover and release the retaining latch. Third, place an ordinary iron brace in the sweeping arm's stopper during its clear phase, then withdraw the now-unloaded pin. Normal attraction activations cost the usual 6 battery; a fitting's large, visible E interaction confirms its physically satisfied state for free, without a hold-to-unlock timer. Invalid state explains the missing condition and spends nothing. Completed fitting state persists. The layout provides the cradle, iron brace and readable safe approach; no rare module is a key. Finally secure the core, choose the safe press phase and take it to the receiver. A baseline route must be demonstrated with a generous battery margin; an analytical action-count budget alone does not establish the route's readability or enjoyment.

| Family | Different release/transport solution, with a real decision |
| --- | --- |
| Surgery | Reach the safe exposed seam, sever the support-release sequence, then extract/preserve the released device. Cutting the obscured load-bearing seam first risks a swing; its anchored core cannot be directly plucked. |
| Demolition | Aim a junk slug through the obstruction and into a brace; spend another shot or accept reduced intact quality to open the route. Plan the line to avoid hitting the core. |
| Conduction | Position conductive scrap/tether so a finite source releases powered clamps, grounding the damaging branch; service any mechanical remainder normally. Decide which source to consume before the final transfer. |
| Rigging | Support the assembly with a placed counterweight, release preload by tension, then tow around the arm/press instead of carrying through its center. A second anchor changes the route. |
| Vector/repulsion | Push the obstructing brace into a stopper position, rotate the released core toward the guide path and redirect it across the lane during a safe phase. Direction/geometry determine what opens and where the value goes. |
| Field lattice | Place a transfer source and receiver on opposite safe sides, use a field/ballast placement to hold the arm clear, then transfer the released core without moving the magnet through that lane. Placement range, blocked lines and the paid transfer matter. |

These are encounter requirements, not claims that six solutions are already simulated. At least two distinct built rigs must pass every mandatory site; the universal fallback must remain available. Optional shortcuts may strongly favor one family. Vector and lattice deserve family status only after observed directional/placement decisions; orbit alone is currently a support concept, not a seventh proven style.

## Acceptance, limits and peer reconciliation

Agreed with the economy designer and gameplay critic: bounded installed slots; permanent discovery with an explicitly separate run economy; physical goal independent of score multipliers; visible partial refining progress; finite sources; real multi-target attraction; accessible fallback routes; no loss of the previous career. We removed the redundant power budget and four active smelts. The economy designer's four purchase/pivot sequences must use the prices above and show affordable useful choices, including a run that rationally declines a keystone.

The remaining substantive disagreement is **whether bounded field activations preserve the attraction feel**. The critic requires a direct comparison with continuous pull, and the producer accepts that requirement. Another unresolved hypothesis is whether the final service fallback is satisfying or feels like chores; three differently approached fittings are an experimental encounter, not established fun. Run-reset preference still needs the producer's owner-facing explanation/decision. Battery prices, output thresholds and catalogue breadth remain tunable.

Smallest next experiment: an isolated expedition mechanics lab with one representative mixed worksite, baseline attraction, selected extraction, launch/slug, tether, a finite conductive source and a real bank ledger. Demonstrate the two cross-family chains and a physically different core route before adding the full catalogue. Keep all six families in the design; do not label the first subset the complete requested game.

Observable acceptance:

1. Changing a module changes the recorded player action/route or reachable outcome, not only completion speed or reward numbers. Demonstrate the exact baseline inability and enabled result.
2. The two cross-family chains work through shared operations, including target/cost previews, failure and mass/source conservation.
3. A whole attempted cast commits at most once; no idle/paused drain; no resource reset after interruption, drop, focus loss or reload. No free energy/value loop from generated effects.
4. Offer sequences permit at least four materially different builds and an affordable pivot. All six final approaches have implementable inputs and a testable opportunity; missing primitives stay labelled missing.
5. A player can explain the next physical goal, what an offered module changes, its cost, and what is lost on failure without external coaching.

Short owner playtest question: **“What did your last module let you do that your previous rig could not, and which different build would you voluntarily try next?”** Record actual actions, confusion, abandonment and voluntary replay. Agent agreement, code compilation, combination counts and this document are not evidence of fun.
