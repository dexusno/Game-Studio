# Cinderwall content contract

P00 compiles the existing Mara/tier-1 eligibility into one reproducible boundary. It is data and structural validation, not an effect executor, a playable build or balance evidence. `runtime-support.json` deliberately starts empty. Temporary runtime staging must not trim the final eligible pools.

Run from the repository root with Python 3.10 or later:

```powershell
python -X utf8 games/overkill-foundry/tools/compile_content.py
python -X utf8 games/overkill-foundry/tools/compile_content.py --check --self-test
python -X utf8 games/overkill-foundry/tools/compile_content.py --check --release
```

The last command **must fail while support is incomplete**. Compilation uses only Python's standard library. It writes `catalogue.snapshot.json` and `cinderwall.manifest.json`, with sorted keys, fixed line endings, source hashes and no timestamps or machine paths. `--check` compares exact regenerated bytes and writes nothing. Any input/compiler change requires regeneration.

During expanded runtime tests, the compiler's original exact-heading parser was found to skip `Rare — manual grab enhancements`; SH121–SH123 incorrectly inherited Legendary. The parser now recognizes the descriptive heading and checks those three Rare IDs explicitly. Regeneration adds them to the Regular pool without changing the 246 eligible IDs or source catalogue. Current manifest SHA-256 is `d56bf01290f16567cd7009a64f4d49f825454a7149fbf6a922a695a4b71deab9`; the earlier foundation report identifies the earlier bytes and is historical evidence.

`catalogue.snapshot.json` preserves all 606 recipe rows, 288 upgrade records and 42 robot rows, not only this city's subset. Recipe/robot/status rows retain exact source text and line references; upgrades retain every original JSON field and a source JSON pointer. Relevant rule documents, the complete beta inputs and resale registry are also preserved. The original design sources remain authoritative. Source-text presence does not make an effect executable.

`cinderwall-authored.json` contains the city gates, named formations, robot action identities and the three new complete Mystery outcomes. `generated-output-annotations.json` supplements the existing resale mappings with generic grants, copy selectors and nested offers. Amounts, timings, costs and conditions remain attached to exact source effects; these annotations never calculate combat. The output graph covers future grants from copied physical parts as well as immediate outputs. Generic part types preserve their original generated amount for resale; later bonuses or depletion do not reprice them.

The teaching formation is `C1-F-MITE-RAM`: slot 1 is C1-R01 at 7 HP; slot 2 is C1-R02 at 24 HP. Ram keeps Armor 3 and Charge → 18-damage blast. No initial solitary Mite is legal. Coil Nest creates at most one live Mite from four lifetime supplies; Split Chassis creates one on death. A lone survivor/death-spawn remains permitted. The chassis's core is 35 Credits and the destroyed Mite's is 5; there is no second payment for an unspawned or escaped body.

Positions 1–3 have three opening Regular templates. Positions 4–6 add Press/Binder; 7–10 also admit Nest. Position 11 returns to opening/middle with no Officer; position 12 offers the sole boss. Three nonadjacent Officer opportunities fall in 4–10 and three Mystery opportunities in 4–11. There are 560 legal category schedules and 6,160 ordinary offer states; the structural validator enumerates all of them. It does not simulate combat or prove first-exposure comprehension.

Mara commits to a Foundry, Patrol or Workshop lane at positions 4 and 8, through 6 and 10 respectively. The district weights favor existing formations 2:1 and never bypass gates. The shared encounter at position 7 is not a free reward/heal. Preserve route/offer seeds, resolved records and seen-mechanic history. Cable Binder's alternate packet is enabled only after its default has been introduced; all other enemies retain their authored reference sequences and conditional branches.

The Mystery category weights remain 40/30/30. Backlot Patrol is a legal current-band Regular fight. Night Exchange offers a finite Uncommon/Rare recipe pair and a Shop-source upgrade at the existing price rules; it never restocks the ordinary shop. Field Calibration offers three eligible Mystery upgrades for a disclosed 8-current-HP payment, with refusal always available. Validate that payment together with the chosen upgrade's own acquisition costs and leave at least 1 HP. A successful or declined noncombat visit completes once with 10 salvage Credits, subject to UGS-113's optional Common-upgrade replacement. Offers, nested choices, purchases and completion receipts persist. Noncombat visits have no combat-victory hooks.

These new numerical Mystery inputs and district weighting assignments are configurable, untested authoring choices within the authorized scope. UGS-089 uses current Regular recipe weights for its ordinary acquisition offers. Exhausted ordinary upgrade rewards use 30 Credits; shops suppress exhausted slots, calibration retains free refusal, and UGS-113 retains its normal Credit reward. These routine authored defaults are labelled in `authored_tuning`; they are not additional owner decisions. No unresolved source contradiction was found that blocks this manifest. Older pending-scope/default timing prose is superseded by the current MVP/timing contracts; specific recipe and upgrade exceptions remain.

For integration, load the manifest and snapshot by their hashes, then bind each entry in `required_runtime_operations` to the authoritative C++ core. Multiple data IDs may share a parameterized handler, but their full source effects and applicable fixtures must be covered. Currently 665 obligations exist, including shared actions/save transactions and content handlers. A part type needs materialization/copy/resale/lifetime support, not a separate damage formula in the client. UI and policies submit legal core actions and consume results. Unknown content must cause an explicit staging/release error, never fall through to a generic effect or silent no-op.

When independent shared-core evidence exists, the integration owner can populate `runtime-support.json`:

```json
{
  "schema_version": 1,
  "manifest_sha256": "the compiler's current manifest hash",
  "verified_build": "an actual build identity",
  "bindings": {
    "recipe:SH001": {
      "handler": "the real registered handler name",
      "implementation": {"path": "core/path-to-real-source.cpp", "sha256": "actual file hash"},
      "tests": ["actual-fixture-id"],
      "evidence": {"path": "core/path-to-test-result.json", "sha256": "actual file hash"}
    }
  }
}
```

Evidence JSON must contain the matching `verified_build`, `manifest_sha256` and `tests` records shaped as `{"id":"actual-fixture-id","result":"passed"}`. Paths are relative to the game directory. The gate checks all obligations, source/evidence hashes and recorded passing fixture IDs. It verifies evidence linkage, not whether a test is sufficient; independent QA and the MVP's human acceptance still apply. No bindings or evidence are invented by the compiler.

Observable acceptance includes unchanged source counts, complete eligible offer pools, no Mayor/Legendary leakage into forbidden sources, full nested-output closure with valuation, legal schedules, one live Mite, correct summons, immutable offers/receipts and release refusal for incomplete support. The negative fixtures deliberately attempt a trimmed pool, unknown nested output, paired Mites, rarity/source leakage, an ordinary boss alternative, unpriced output and missing runtime binding. These are data checks, not headless city runs.
