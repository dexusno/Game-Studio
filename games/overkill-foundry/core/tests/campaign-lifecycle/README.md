# Campaign lifecycle contracts

Six named groups pass652 assertions and CTest1/1 against28 unchanged copied
inputs. [evidence.json](evidence.json) records the source graph, binary/library,
full test log and candidate links. No active runtime support binding changes.

Actual production campaign hooks verify:

- Killing a body allocates its correctly valued core; accepting and selling are
  separate actions, with stable identity and no repeated income.
- Ordinary parts sell at the canonical material reference, rounded per part.
  Loaded, installed and used Shield parts cannot be sold; eligible unloading
  and removal restore access without repricing the part.
- Seeing shop/reward alternatives discovers them without acquisition, repeated
  sightings are unique, and skipped rewards retain those facts.
- Patrol entry requires combat; Continue retains its entry; victory grants
  normal rewards and advances/restocks once.
- A real boss victory unlocks Ivo once; finishing rewards completes the city.
  New Game resets economy/supplies/memory while retaining profile facts.

Every accepted command is repeated from its serialized input and compared for
complete state and ordered events. A duplicate receipt retry must return the
same events without a second mutation. Rejected actions preserve all state.

These are prepared contract boundaries: route prefixes, Mayor candidates,
standard grants, one reactive-defense fixture and500-damage terminal ammunition
are controlled inputs. They are not an earned loadout, balance or disk-save test.
The separate earned Unreal city replay uses its explicit historical core and
must not be relabelled as this candidate's graphical verification.

The immutable build is under `core/build/campaign-lifecycle-final/source`.
For a new live-source check, configure this directory with CMake, build Release
and run CTest. The isolated target requires C++17 and strict compiler warnings.
Independent clause review and the rules-version/save decision remain pending.
