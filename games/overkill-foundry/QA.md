# Overkill Foundry — quality and playtesting

No implemented game has been tested.

## Test plan

Define checks for the core loop, controls, restart/failure paths, progression/save behavior, readability, audio, accessibility, performance and target platforms in proportion to the agreed scope.

## Human playtests

For each session record date/build, participant profile, task or question, observed behavior, duration, unprompted reactions, friction, and changes worth testing. Separate observations from interpretations. A model review is not a human playtest.

## Bugs and findings

Use severity, reproduction steps, expected/actual behavior, evidence, owner and retest outcome. No findings recorded yet.

## Decision evidence

Fun is unvalidated. Define advance/revise/park criteria in BRIEF.md before treating playtest results as a production decision.
